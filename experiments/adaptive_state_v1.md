# Adaptive predictive context v1 — development prototype

Status: independently accepted by distinct Codex research_critic, with the clarifications below recorded before implementation. This is a bounded engineering experiment, not a new-method or efficiency claim. The question is whether a simple evidence trigger can activate a useful extra history feature without routinely doing so in stable worlds. Closest model-order/sparse-context prior art is recorded in [the focused audit](../research/state_revision_prior_art.md). This is a deliberately restricted finite model family, not concept invention or an artificial scientist choosing experiments.

## Fixed design, before this run
Use the unchanged v0 world generator: four conditions, 1,200 ticks, evaluator-only change at zero-based tick 600, development seeds 0..4. Same stream for every learner. Seeds 1000..1049 remain unused. No new tuning sweep or threshold adjustment after seeing results; a failure remains a failure in this version.

Each adaptive learner owns a base predictor using lag 1 and four shadow predictors using the pair of observed bits at lags (1,k), k=2..5. A missing observation is represented by -1; no hidden initialization is exposed. All use discounted data counts (0.99) with fixed Beta(1,1) priors, just like v0. The learner predicts from the base initially, and updates all five models after each observed bit.

For each shadow, retain the last 128 pre-update log-likelihood gains over the base: log P_shadow(y) minus log P_base(y). After every 64 observations, once a full window exists (checks after outcomes 128, 192, ...; zero-based ticks 127, 191, ...), select the highest cumulative gain (ties favor smaller k). If its gain is strictly greater than log(400), activate that lag pair starting with the NEXT prediction. This is a heuristic threshold, not a calibrated sequential test, Bayes factor with a claimed guarantee, or p-value. Repeated and overlapping tests are not independent. Selection uses only observed bits and the learner's own observation counter; no world label, change time or true lag.

At most one activation per world in v1; no shrinking, later reselection or arbitrary feature creation. All monitoring continues after activation to keep overhead explicit and make the monitor-only ablation comparable. The shadow bank is present from the beginning: active predictive context expands from one bit to two, but total allocated memory does not begin small or grow only at the decision. Consequently this prototype cannot establish the original resource-saving hypothesis.

## Comparators and accounting
Six learners: existing order1, order5, dense order mixture; a fixed-share (0.01) mixture of the same base and four sparse experts; adaptive activation; and monitor-only (identical bank and gain monitoring, but prediction always uses base). All receive equal observations. No oracle competitor.

Report pre-update probability, losses, total logical storage, active context width/lag, completed monitoring checks, and update events. Logical storage includes every model's context keys, counts, allocated history capacity, sparse lag indices, mixture weights, all four gain buffers at their capacity, and adaptive selection/counter/settings scalars. It excludes Python object overhead and temporary arithmetic, so is not measured RAM. Report measured cumulative prediction/update time per learner separately (timing instrumentation and artifact export excluded); timing from a tiny run is descriptive only. Events record the observation that completed the evidence window, the first affected prediction tick, chosen lag and gain. Evaluator-only true lag appears separately for diagnosis, never as learner input.

## Predetermined descriptive checks
Primary diagnostic: paired seed-level mean post-change log-loss improvement of adaptive over order1 in structural worlds. The tentative engineering screen requires improvement >=0.02 nats, stable mean loss increase <=0.01 nats, and at most 1/5 stable worlds activating at any time, including before tick 600. The stable penalty is also averaged over seed-level post-change differences. All three must hold; this is not a scientific significance test or a final success criterion for the project. Report the sparse-mixture comparison regardless of outcome, plus noise/parameter activations, premature structural activations, lag matches, first activation ticks and no-activation cases. Do not call a pre-change activation successful detection. No calibration or causal inference claim.

Expressive recurrent and faithful context-tree competitors, unseen law families, uncertainty estimates and a genuinely resource-adaptive implementation remain required before a substantive superiority/efficiency claim. Five known development seeds are explicitly not held-out evidence. The existing baseline results informed this prototype design.
