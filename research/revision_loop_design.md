# Assumption-revision laboratory: pre-execution design

Status: reviewed protocol; no learner execution yet. World source frozen at dfabfe1 before learner tuning/execution; draft thresholds were independently specified concurrently. This implements one failure → alternatives → chosen test → revision loop. It is not concept invention or a novelty claim.

## Scope and information boundary

Use the existing public Action/Observation contract and 80 training tool units. A different agent freezes control/challenge/stress dynamics before learner thresholds are adjusted. Control reuses the original simple world; the others are independently authored. Runtime sees only observations/actions/history, never variant labels, hidden state, source or evaluation. Developer source review is not formal blinding. Existing inspected worlds remain development material.

Start with the already available shared motion/input form `delta = a*v + b*u`, fitted from observations; its structure is supplied. This task tests revising its assumptions, not discovering an initial equation from nothing. Models are safe arithmetic programs, no eval/exec, files, network or runtime LLM. Remain within 120 CPU seconds and 10 MB combined trace and prediction journal per run; summary/replay are derived artifacts outside this byte cap.

## General revision operations

Model terms use own-coordinate p,v,u,lag_u,1 and other-coordinate p,v,u,lag_u. An axis may share coefficients with the other axis or fit separately. Primitive operations remain absolute value, positive part and multiplication; no new simulator-specific operator. Maximum four additive terms per coordinate, maximum40 AST nodes across terms and nesting depth12, same term list, either shared or separate coefficients. Append edits always use separate coefficients; unsharing is a separate zero-new-term alternative. Ridge 1e-4, coefficient clamp ±10, predicted state clamp ±1000; deterministic IDs/ties.

At each triggered revision propose at most three alternatives, one best training-score edit per family: (1) unshare coefficients; (2) append one unused primitive variable, using separate coefficients; (3) append one unused unary/product term, using separate coefficients. The third family's finite menu is the previous own-coordinate nonlinear grammar plus same-type own×other products for p,v,u. Select within each family by training mean squared 2D displacement error + 1e-4 times parameter count. Deduplicate; exclude incumbent. Max two revision cycles. These operations explicitly encode designer assumptions; nothing certifies them as complete.

## Experiments and chronology

Use a declared subset of the public tools: each experiment is one of eight cardinal pushes (magnitudes .3/1) followed by observe, or observe followed by observe. Each costs two units. This deliberate two-observation design avoids fitting instantaneous motion from multi-tick averages; it is not an expansion of the simulator API. Same menu for active/random/coverage/no-revision controls. Six initial experiments use coverage for all revision policies; only this six-experiment prefix is guaranteed identical across them, not arbitrary later pre-trigger histories. Reset is available in the API but not selected in this bounded menu; its evaluation cost remains counted separately.

Before an experiment, freeze complete two-step predicted position tapes for all current alternatives. Execute both tools, recording both outcomes, then compare predictions. Within a revision check, coefficients stay frozen for all four experiments (eight tool units); predictions for each experiment start from its newly available public state/history. No fitting on these check observations until adoption is decided. All alternatives face exactly the same observed outcomes.

Outside checks, refit the incumbent on all eligible one-tick history. Maintain the last five experiment losses, each the mean squared 2D position error over its two predictions. After warmup, trigger if at least three of these five exceed `max(.0025,12*home_variance)`, at least eight tool units remain, and at least six experiments have elapsed since a prior check ended. Log this fixed threshold in every experiment. Home variance is initial squared position averaged across coordinates with floor1e-4; fixed independent-sensor assumption, not a calibrated uncertainty estimate. Never reclassify dynamics errors as noise. Clear trigger window after a completed check. At most two triggers; insufficient evidence/budget is recorded.

During checks, active selects the experiment maximizing `(min(1,max(0,mean committee position variance - 2*home_variance)) + .02/(1+visits))/2`. Variance uses equal weights across frozen incumbent plus alternatives, averaged over both tape positions. This is a heuristic disagreement score, not expected information gain. Random chooses uniformly; coverage chooses least visited. Outside checks, all use their declared exploration rule, with active falling back to coverage when only incumbent exists. Ties follow fixed menu order.

Order is trigger on frozen pre-outcome losses, refit/propose using history through that triggering experiment, freeze every model for four future checks, decide adoption before refitting on those checks, then refit. The check data are adaptively collected screening evidence, not an unbiased holdout or a hypothesis test.

After four check experiments, adopt the best alternative only if its check MSE is below incumbent MSE by more than `max(.15*incumbent_MSE,.0001*max(1,extra_parameters))`. Otherwise keep incumbent. Then refit retained structure using all history. Report accepted/rejected plus remaining unexplained-error flags; rejection or a budget stop is not proof of impossibility. The significance of the numeric margin is practical and heuristic, not a false-discovery guarantee.

## Controls and success, fixed before runs

Run active, random and coverage with identical revision mechanics; run no-revision coverage as a fixed shared starting-model control. Also run the original enumerating active learner with its original tool menu at the same 80-unit budget; report that menu difference. On every run's own training data, fit an evaluator-only ordinary vector linear regression over all nine primitive inputs; this tests whether sophisticated selection earns any benefit beyond generic fitting. This reference uses separate coefficients for each axis over all nine local/other primitive inputs, the same eligible rows, ridge 1e-4 and ±10 coefficient clamp. Empty data returns zero coefficients; ridge and deterministic pivot ties handle collinearity. It never guides the learner. No-revision skips all triggers, proposals and checks; it follows coverage for the entire80 units.

Evaluate each frozen final model on the original three off-menu intervention sequences plus a fourth: push(angle=.61,magnitude=.8), wait(4), push(angle=2.43,magnitude=.6), wait(4), push(angle=4.72,magnitude=.4), wait(4), observe. That fourth sequence advances16 ticks and costs24 including initial reset. Use these same four sequences for every policy, original enumerator and fitted reference, 68 evaluator tool units total, with paired noise streams across policies. Outcomes never enter model adoption. Compare mean squared 2D position error, cycle decisions, experiment scores, prediction tapes, work costs and false/unnecessary expansions. Two distinct descriptive screens: useful revision requires active mean challenge error at least20% below no-revision coverage with improvement in at least2/3 paired seeds; useful experiment selection requires active mean challenge error at least10% below each matched random and coverage revision policy, with improvement in at least2/3 seeds against each. Original enumerator is an unmatched reference, not a required screen. Control non-regression requires active mean error no greater than1.25 times no-revision plus .0001; a clean no-unnecessary-expansion result additionally requires zero adoptions in all3 controls. Report every screen separately. Credit beyond same-data vector regression requires active mean challenge error at least10% lower, or within1% with fewer fitted parameters in every challenge seed; otherwise do not claim the revision machinery adds value beyond generic fitting. All thresholds are practical descriptive screens, not statistical tests. Functional integration requires all3 active challenge runs to reach a recorded revision check and resolve it by adoption/rejection; zero triggers is reported as failure to demonstrate the loop, never replaced by a handpicked successful run. For every cycle report frozen check loss gaps and, after the run only, evaluate those frozen candidate snapshots on the same external outcome tapes to report descriptive agreement between internal and external adoption decisions using the same15%/parameter margin, separately logging accept/reject agreement and exact selected-model agreement. This diagnostic never returns to the learner and consumes no extra world observations. Final adoption is not evidence of true-law recovery. Record control expansions and stress unresolved outcomes separately; do not label a single passed check as discovery. No adoption claim should imply true-law recovery.

Three worlds × three seeds (270001,270002,270003) × five policies =45 bounded runs, sequentially, with no tuning or added seeds after observing outcomes. Mean paired errors and per-seed results are descriptive, not significance estimates; a control expansion prevents a clean no-unnecessary-expansion claim. Stress tests explanation limits, not a mathematical impossibility claim. The comparison changes model capacity and, for the original enumerator, tool menu; it cannot attribute an overall gain to revision alone. No broad sweep. Freeze source, thresholds, worlds and this protocol before execution; no world smoke with learner before that freeze. Tests use synthetic fixtures only.

## Deliverable

A replay of one predeclared challenge/active/first-seed run: old formula, recorded failure, alternatives, prospective experiment choice, outcomes, check errors, adopted formula or unresolved result. Browser verification must be reported separately. Preserve all failures and raw runs. Claude reviews design; another agent reviews all code and results. End after this comparison with a short report; no automatic next experiment or extra spending.

## Review decisions before implementation

[Claude critique](claude_revision_design.md) and [provenance](revision_claude_provenance.json). Accepted exact chronology, generic-operation provenance, weak known-home noise assumption, paired-prefix verification, separate selection/revision screens with explicit counts/tolerances, and same-data regression credit. The world author saw the general revision-outline operations (axis separation, cross components, nonlinear/history) before writing worlds, but not tuned thresholds or learner outcomes. Therefore these worlds test declared capabilities, not blind generalization. Evaluator-owned source-capacity classification is reported separately after runs.

Independent review identified exact evaluator and reference ambiguities; all policies now use the same four sequences and68evaluation units. The16tick sequence was added before execution because the original short evaluator would miss delayed effects. No world coefficients were changed.

We decline Claude's suggestion to estimate measurement noise from successive moving-world observations: dynamics would contaminate that estimate. The known-home assumption remains explicit. We also decline pre-freeze learner smoke/tuning and replay cherry-picking. Synthetic tests check the mechanics; the declared first-seed replay must show non-triggering/failure honestly if that occurs. Only16of80units can be directed by competing explanations; this small opportunity is disclosed, and failure is informative. The screen is descriptive at this scale, not a claim of statistical power.
