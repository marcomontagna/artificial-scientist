# Workflow: one complete investigator

Read README, direction and the tool-lab design. The user's active instruction is to build a coherent investigator, with no further disconnected statistical exercises.

1. Implement one complete observe/propose/predict/act/revise loop using established components. State inputs, tool limits, model assumptions and what is still missing.
2. Use separate ownership for the hidden world and learner where practical. Give the runtime learner only observations and permitted tools; keep evaluator labels outside its decisions.
3. Ask Claude to challenge important design decisions through existing authorized access. Get another agent to review substantive code and artifacts. Record actual findings and fixes briefly in review_log.md; do not imply approval when a critic disagreed.
4. Run focused correctness/leakage tests and a bounded integration demonstration. Log predicted outcomes before observed outcomes, tool/search budgets and failure states. Preserve raw traces; compare simple alternatives within this working system.
5. Show the actual investigation. Then decide whether the next capability fixes a demonstrated limitation. More components, larger grammars, new statistical studies or new papers are not progress by themselves.

A useful prototype may be built from known methods. A claim of original science needs a specific result beyond the closest prior art and strong baselines; that separate burden must not turn every implementation into another literature/statistics detour.

No extra spending, paid fallback, global installation, unrelated filesystem changes or unbounded jobs. Keep results fresh and reproducible. Keep reports short.
